Disk (EBS)

No target metal instance type has instance store, so all sandbox I/O lands on the EBS volume behind /data/cubelet. Reads should be near zero after warmup: sandboxes restore from a per-node memory snapshot through reflink copy-on-write, so an untouched page is shared rather than re-read. Writes are per-rollout lifecycle churn - a CoW upper layer, a shim log and a snapshot pack created and destroyed for every rollout - which makes the load IOPS-shaped rather than bandwidth-shaped.

Read await, not util. For a network-attached volume, util only means "at least one I/O in flight" and can sit high while far from the provisioned limit (measured: 43-56% util at ~740 IOPS on a 10,000 IOPS gp3). EBS throttles by queueing, so rising service time with flat throughput is the real signal. gp3 normally serves in ~1 ms.
